# Angular Event Binding and `$event`

## 1. Quick recap

Angular data binding connects the component class with its HTML template.

```text
TypeScript class → data and logic
HTML template    → displayed content and user actions
```

The main binding types are:

| Binding | Syntax | Purpose |
|---|---|---|
| Interpolation | `{{ value }}` | Displays data as text |
| Property binding | `[property]="value"` | Sets an element property |
| Event binding | `(event)="method()"` | Responds to user actions |
| Two-way binding | `[(ngModel)]="value"` | Keeps data synchronized in both directions |

This lesson focuses on event binding and reading event data with `$event`.

---

# 2. What is event binding?

An event is an action that happens on the page.

Examples include:

- Clicking a button
- Typing in an input
- Submitting a form
- Selecting a dropdown option
- Pressing a keyboard key
- Moving the mouse over an element

Event binding allows Angular to listen for these actions and call a method in the component class.

```html
<button (click)="onSave()">
  Save
</button>
```

This means:

> When the button is clicked, call the `onSave()` method.

---

# 3. Event binding syntax

The general syntax is:

```html
<element (eventName)="componentMethod()"></element>
```

For example:

```html
<input
  type="text"
  (input)="onNameChange($event)">
```

This contains three important parts:

| Part | Meaning |
|---|---|
| `input` | The event Angular should listen for |
| `onNameChange` | The component method to call |
| `$event` | Information about the event |

---

# 4. Direction of event binding

Interpolation and property binding send data from the component to the template:

```text
Component → Template
```

Event binding works in the opposite direction:

```text
Template → Component
```

The complete flow is:

```text
User performs an action
        ↓
Browser creates an event object
        ↓
Angular receives the event
        ↓
Angular calls the component method
        ↓
The method handles the event data
```

---

# 5. Simple click example

## Component class

```typescript
export class DataBinding {
  message = '';

  onSave() {
    console.log('Button clicked!');
    this.message = 'Your data was saved.';
  }
}
```

## Template

```html
<button
  type="button"
  (click)="onSave()">
  Save
</button>

<p>{{ message }}</p>
```

When the button is clicked:

```text
(click)="onSave()"
        ↓
onSave() runs
        ↓
message changes
        ↓
{{ message }} displays the new value
```

The browser console shows:

```text
Button clicked!
```

The page displays:

```text
Your data was saved.
```

# 6. What is `$event`?

`$event` is a special Angular variable that contains information about the event that occurred.

Important:

> `$event` is not automatically the text typed by the user.

For a normal input event, `$event` is an event object. The typed value is inside:

```typescript
event.target.value
```

Example:

```html
<input
  type="text"
  (input)="onNameChange($event)">
```

```typescript
username = '';

onNameChange(event: Event): void {
  const inputElement = event.target as HTMLInputElement;
  this.username = inputElement.value;
}
```

Here:

- `event` represents the complete event.
- `event.target` represents the element that triggered the event.
- `as HTMLInputElement` tells TypeScript that the element is an input.
- `.value` retrieves the text inside the input.

# 7. Handling input text

## Template

```html
<input
  type="text"
  placeholder="Enter your name"
  (input)="onInput($event)">

<p>You typed: {{ username }}</p>
```

## Component class

```typescript
export class DataBinding {
  username = '';

  onInput(event: Event): void {
    const input = event.target as HTMLInputElement;
    this.username = input.value;
  }
}
```

## What happens when the user types?

```text
1. The user types a character.
2. The browser fires an input event.
3. Angular calls onInput($event).
4. The method reads input.value.
5. username is updated.
6. {{ username }} displays the new value.
```

If the user types:

```text
Abhilash
```

Then:

```typescript
input.value
```

contains:

```text
Abhilash
```

# 8. Different events provide different data

The type of information available depends on the event and the element.

## 8.1 Click event

```html
<button
  type="button"
  (click)="handleClick($event)">
  Submit
</button>
```

```typescript
handleClick(event: MouseEvent): void {
  console.log(event.type);
  console.log(event.target);
}
```

A click event is a `MouseEvent`.

---

## 8.2 Number input

```html
<input
  type="number"
  (input)="onAgeChange($event)">
```

```typescript
onAgeChange(event: Event): void {
  const input = event.target as HTMLInputElement;

  const age: number = input.valueAsNumber;

  console.log(age);
}
```

Even when the input uses:

```html
type="number"
```

the normal `input.value` is still a string.

Use:

```typescript
input.valueAsNumber
```

to read the value as a number.

An empty or invalid number input can produce:

```text
NaN
```

---

## 8.3 Checkbox

For a checkbox, use `.checked` instead of `.value`.

```html
<input
  type="checkbox"
  (change)="onCheckboxChange($event)">
```

```typescript
onCheckboxChange(event: Event): void {
  const checkbox = event.target as HTMLInputElement;

  console.log(checkbox.checked);
}
```

The result is either:

```text
true
```

or:

```text
false
```

---

## 8.4 Dropdown

```html
<select (change)="onCountryChange($event)">
  <option value="IN">India</option>
  <option value="US">USA</option>
</select>
```

```typescript
onCountryChange(event: Event): void {
  const select = event.target as HTMLSelectElement;

  console.log(select.value);
}
```

If the user selects India, the value is:

```text
IN
```

---

## 8.5 Keyboard event

```html
<input
  type="text"
  (keyup)="onKeyUp($event)">
```

```typescript
onKeyUp(event: KeyboardEvent): void {
  console.log(event.key);
}
```

If the user presses the `A` key, `event.key` usually contains:

```text
a
```

or:

```text
A
```

depending on whether Shift is being used.

# 9. Passing your own value to a method

You do not always need `$event`. You can pass your own value directly.

## Template

```html
<button
  type="button"
  (click)="greet('Abhi')">
  Say Hello
</button>
```

## Component class

```typescript
greet(name: string): void {
  console.log('Hello ' + name);
}
```

When the button is clicked, the console shows:

```text
Hello Abhi
```

---

# 10. Passing an input value directly

Instead of passing the complete event object, you can pass only the input value.

```html
<input
  #nameInput
  type="text"
  (input)="onNameChange(nameInput.value)">
```

```typescript
onNameChange(value: string): void {
  this.username = value;
}
```

Here:

```html
#nameInput
```

creates a template reference variable for the input element.

Then:

```html
nameInput.value
```

gets the current input value.

This approach is often simpler when the method only needs the value.

---

# 11. Alternative: two-way binding

For simple forms, two-way binding can keep the input and component property synchronized automatically.

```typescript
username = '';
```

```html
<input
  [(ngModel)]="username"
  placeholder="Enter your name">

<p>{{ username }}</p>
```

This requires `FormsModule`.

```typescript
import { FormsModule } from '@angular/forms';

@Component({
  imports: [FormsModule]
})
```

Two-way binding is useful when you do not need to manually process the event.

---

# 12. Reactive forms

For larger forms with detailed validation and form-state management, Angular also provides reactive forms.

Example:

```typescript
import { FormControl } from '@angular/forms';

username = new FormControl('');
```

```html
<input [formControl]="username">

<p>{{ username.value }}</p>
```

Reactive forms require:

```typescript
ReactiveFormsModule
```

For now, focus on understanding normal event binding first.

# 13. TypeScript concepts used with `$event`

## Event type

```typescript
onNameChange(event: Event): void {
}
```

`Event` tells TypeScript that the method receives an event object.

For specific events, you can use more specific types:

```typescript
handleClick(event: MouseEvent): void {
}

onKeyUp(event: KeyboardEvent): void {
}
```

## Type assertion

```typescript
const input = event.target as HTMLInputElement;
```

The `target` property is broadly typed as `EventTarget`. TypeScript does not automatically know that it has a `.value` property.

The assertion tells TypeScript:

> Treat this target as an HTML input element.

It does not convert the object at runtime. It only provides compile-time type information.

# 14. Common mistakes

## Mistake 1: Using square brackets instead of round brackets

Incorrect:

```html
<button [click]="onSave()">
  Save
</button>
```

Correct:

```html
<button (click)="onSave()">
  Save
</button>
```

Remember:

```text
[ ] → property binding
( ) → event binding
```

---

## Mistake 2: Writing `onclick`

Incorrect:

```html
<button (onclick)="onSave()">
  Save
</button>
```

Correct:

```html
<button (click)="onSave()">
  Save
</button>
```

Angular uses only the event name inside the parentheses.

```text
Normal HTML: onclick
Angular:     (click)
```

---

## Mistake 3: Forgetting the method parentheses

Incorrect:

```html
<button (click)="onSave">
  Save
</button>
```

Correct:

```html
<button (click)="onSave()">
  Save
</button>
```

The parentheses call the method when the event occurs.

---

## Mistake 4: Using `this` in the template

Incorrect:

```html
<button (click)="this.onSave()">
  Save
</button>
```

Correct:

```html
<button (click)="onSave()">
  Save
</button>
```

Use `this` in TypeScript, but not in Angular templates.

---

# 15. Event binding with other bindings

Real applications often use multiple binding types together.

## Component class

```typescript
export class Counter {
  count = 0;

  increase(): void {
    this.count++;
  }

  decrease(): void {
    if (this.count > 0) {
      this.count--;
    }
  }

  reset(): void {
    this.count = 0;
  }
}
```

## Template

```html
<h2>Count: {{ count }}</h2>

<button
  type="button"
  (click)="increase()">
  Increase
</button>

<button
  type="button"
  [disabled]="count === 0"
  (click)="decrease()">
  Decrease
</button>

<button
  type="button"
  (click)="reset()">
  Reset
</button>
```

This example uses:

```text
{{ count }}          → interpolation
[disabled]="..."     → property binding
(click)="..."        → event binding
```

# 16. Event binding and backend communication

Event binding itself does not send data to a backend.

It only calls a component method:

```html
<button (click)="onSave()">
  Save
</button>
```

The method can later call a service:

```typescript
onSave(): void {
  // Prepare the data.
  // Call a service.
  // Send the data to an API.
}
```

The general flow is:

```text
User clicks Save
        ↓
Event binding calls onSave()
        ↓
The component prepares the data
        ↓
A service can send the data to an API
```

Backend communication is a separate topic. At this stage, practise by updating properties and using `console.log()`.

# Quick revision

Event binding listens for user actions and calls component methods.

Basic syntax:

```html
(event)="method()"
```

Example:

```html
<button (click)="onSave()">
  Save
</button>
```

When event information is needed:

```html
<input (input)="onInput($event)">
```

```typescript
onInput(event: Event): void {
  const input = event.target as HTMLInputElement;
  this.username = input.value;
}
```

Remember:

- Event binding uses round brackets.
- `$event` contains the event object.
- Use `event.target` to identify the element that triggered the event.
- Use a type assertion such as `as HTMLInputElement` when needed.
- Use `.value` for text inputs.
- Use `.valueAsNumber` for numeric input values.
- Use `.checked` for checkboxes.
- Use `.key` for keyboard events.
- Do not use `onclick`; use `(click)`.
- Do not use `this.` inside the template.

## One-line takeaway

> Event binding connects an HTML event to a TypeScript method, while `$event` gives the method information about what happened.
