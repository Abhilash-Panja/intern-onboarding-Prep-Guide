# Angular Event Binding for Beginners

*Part 3 of my Angular data binding series*

In the first two posts, I learned about **interpolation** and **property binding**. In both, data flows from the TypeScript file to the page. But what happens when the user *does* something, like clicking a button or typing in a box? That is where **event binding** comes in.

## 1. A Quick Recap

Data binding is the connection between the TypeScript file (`.ts`), which holds the data and logic, and the HTML file (`.html`), which shows the page.

Angular has four types:

1. **Interpolation (`{{ }}`):** Shows data as text.
2. **Property binding (`[ ]`):** Sets element properties using data.
3. **Event binding (`( )`):** Reacts to user actions.
4. **Two-way binding (`[( )]`):** Keeps data and inputs in sync.

Today's topic is number 3.

## 2. What Is Event Binding?

An **event** is something the end user does on the page. For example:

- Clicking a button (`click`).
- Typing in an input box (`input`).
- Submitting a form (`submit`).
- Moving the mouse over an element (`mouseover`).

**Event binding lets you process the user's action.** When the event happens, Angular runs a method that you wrote in the `.ts` file.

You write the event name inside **round brackets** `( )`:

```html
<button (click)="onSave()">Save</button>
```

Here, when the user clicks the button, Angular calls the `onSave()` method from the component.

## 3. The Direction of Data Flow

This is the key difference from the earlier bindings:

- **Interpolation and property binding:** Component (`.ts`) to template (HTML).
- **Event binding:** Template (HTML) to component (`.ts`).

The user does something on the page, and the event triggers a method in your TypeScript code to handle it.

## 4. How to Use Event Binding: Step by Step

### Step 1: Write a Method in the TypeScript File

Open `data-binding.ts` and add a method and a property:

```typescript
export class DataBinding {
  message = '';

  onSave() {
    console.log('Button clicked!');
  }
}
```

### Step 2: Bind the Event in the HTML File

Open `data-binding.html`:

```html
<button (click)="onSave()">Save</button>
```

### Step 3: Test It

Run the app, open the browser, press **F12**, and go to the **Console** tab.

Each time you click the button, you will see:

```text
Button clicked!
```

## 5. Getting the User's Input with `$event`

Sometimes you need to know *what* the user did, such as what they typed. Angular gives you a special value called **`$event`**, which carries the details of the event.

### In the TypeScript File

```typescript
export class DataBinding {
  message = '';

  onTyping(event: Event) {
    const input = event.target as HTMLInputElement;
    this.message = input.value;
  }
}
```

### In the HTML File

```html
<input (input)="onTyping($event)" placeholder="Type something" />

<p>You typed: {{ message }}</p>
```

Here is what happens on every keystroke:

1. The user types a letter.
2. `(input)` catches the event and calls `onTyping($event)`.
3. The method reads the typed text and saves it in `message`.
4. Interpolation (`{{ message }}`) shows the updated text on the page.

This example uses two types of binding together, and that is how real Angular apps work.

## 6. Passing Your Own Values

You can also pass values to the method yourself.

### HTML

```html
<button (click)="greet('Abhi')">Say Hello</button>
```

### TypeScript

```typescript
greet(name: string) {
  console.log('Hello ' + name);
}
```

When the user clicks the button, the console displays:

```text
Hello Abhi
```

## 7. Common Events You Will Use

| Event | When it happens |
|---|---|
| `(click)` | User clicks an element. |
| `(input)` | User types or edits a value in an input box. |
| `(change)` | A value changes, such as a dropdown selection. |
| `(submit)` | A form is submitted. |
| `(mouseover)` | The mouse moves over an element. |
| `(keyup)` | User releases a key. |

## 8. How Event Binding Connects to a Backend

In real applications, the user's action often needs to be saved. The typical flow is:

1. The user clicks **Save**.
2. `(click)="onSave()"` in the HTML calls the method.
3. The method in the `.ts` file handles the data.
4. The method calls a **service**, which sends the data to the backend API.
5. The backend processes the request and saves the data.

An important point: event binding by itself only **calls your method**. Sending data to the backend is something you write inside that method, usually using a service with Angular's `HttpClient`.

I'll learn that later, so for now I can practise with `console.log` and interpolation.

## 9. Common Mistakes to Avoid

### Mistake 1: Using Square Brackets Instead of Round Brackets

```html
<!-- Wrong -->
<button [click]="onSave()">Save</button>

<!-- Correct -->
<button (click)="onSave()">Save</button>
```

Round brackets are for events. Square brackets are for properties.

### Mistake 2: Writing `on` Before the Event Name

```html
<!-- Wrong -->
<button (onclick)="onSave()">Save</button>

<!-- Correct -->
<button (click)="onSave()">Save</button>
```

In normal HTML, you write `onclick` as an event-handler attribute. In Angular event binding, you write just `click` inside the round brackets.

### Mistake 3: Forgetting the Method Brackets

```html
<!-- Wrong for calling the method -->
<button (click)="onSave">Save</button>

<!-- Correct -->
<button (click)="onSave()">Save</button>
```

The first example references the method instead of invoking it. The second calls the method when the event occurs.

## 10. Rules to Remember

- Event binding uses **round brackets** `( )` around the event name.
- The event triggers a method in the component.
- The value in quotes is the expression Angular evaluates when the event happens.
- Use `$event` when you need details about what the user did.
- Don't write `this.` in the HTML file.

## 11. Comparison of All Four Bindings

| Binding | Syntax | Direction | Used for |
|---|---|---|---|
| Interpolation | `{{ }}` | Component to page | Showing text |
| Property binding | `[ ]` | Component to element | Setting element properties |
| Event binding | `( )` | Template to component | Reacting to user actions |
| Two-way binding | `[( )]` | Both ways | Keeping inputs and data in sync |

## 12. A Little Practice Task

Build a small **Counter**.

1. In the `.ts` file, add `count = 0`.
2. Add three methods: `increase()`, `decrease()`, and `reset()`.
3. In the HTML, add three buttons using `(click)`.
4. Show the count using `{{ count }}`.
5. **Bonus:** Disable the decrease button when the count is 0 using `[disabled]="count === 0"`.

This task uses interpolation, property binding, and event binding together.

Try to complete the task yourself before looking for a solution.

## 13. Summary

- **Event binding** lets you respond to user actions like clicks and typing.
- It uses **round brackets** `( )`, for example `(click)` and `(input)`.
- The event triggers a method in the component.
- That method can later call a backend API to save data.
- `$event` gives you details about what the user did.

Next up is **two-way binding**, which combines property binding and event binding into one.
