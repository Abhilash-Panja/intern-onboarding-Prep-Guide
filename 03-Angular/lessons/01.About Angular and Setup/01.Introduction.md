# Day 1 — Angular Foundations, Windows Setup, and Your First Application

### Prerequisites

You only need basic familiarity with HTML tags, CSS selectors, and folders/files. JavaScript and TypeScript fundamentals will be introduced progressively.

---

## Part 1 — Understand Angular before installing it

### 1. Why would a team use Angular?

To understand why Angular is useful, first compare a small website with a large application.

#### A small website

Suppose a clinic needs a simple website with:

- Clinic address
- Consultation timings
- Contact information
- A button

This can be built using:

```text
HTML       → page structure
CSS        → appearance and layout
JavaScript → button behavior and interaction
```

For a small website, this approach works well.

---

#### When the application becomes larger

Later, the clinic needs a complete appointment application:

- Patients book appointments.
- Staff manage schedules.
- Doctors view their appointments.
- Different users see different screens.
- Appointment data changes frequently.
- The same buttons, forms, and cards are reused.
- Several developers work on the project.

Now the application is no longer just a few pages. It contains many screens, features, data, and user interactions.

---

#### The problem with using only plain JavaScript

Plain JavaScript can still build this application, but the team must decide and maintain its own rules for:

- Organizing files
- Dividing the application into parts
- Updating the page when data changes
- Reusing common user-interface elements
- Managing navigation
- Handling forms
- Sharing logic between features

If every developer follows a different style, the code can become:

- Difficult to understand
- Difficult to reuse
- Difficult to test
- Difficult to update
- Difficult for new developers to learn

---

#### How Angular helps

Angular provides a structured way to build and organize large web applications.

It gives developers features such as:

| Requirement | Angular solution |
|---|---|
| Divide the screen into reusable parts | Components |
| Display data in HTML | Templates and data binding |
| Respond to user actions | Event handling |
| Move between pages | Routing |
| Manage forms | Form tools and validation |
| Reuse application logic | Services |
| Create and run projects | Angular CLI |

Angular does not replace HTML, CSS, or JavaScript. Instead, it organizes these technologies into a clear application structure.

```text
HTML + CSS + TypeScript
          ↓
      Angular
          ↓
Structured and interactive web application
```

---

#### Simple example

Without a framework, a team may create its own way of organizing an appointment card, appointment form, and appointment list.

With Angular, these can become separate reusable components:

```text
ClinicApplication
│
├── HeaderComponent
├── AppointmentFormComponent
├── AppointmentListComponent
└── AppointmentCardComponent
```

Each component has its own responsibility, which makes the application easier to understand and maintain.

---

#### Main takeaway

A small website can often be built with HTML, CSS, and JavaScript alone.

As the application grows, Angular helps the team organize the code into reusable components, manage interactions, and follow consistent development practices.

> Angular is a framework that helps teams build and maintain large, interactive web applications in an organized way.

### Angular's role

Angular is an opinionated framework for building interactive web applications. It provides established patterns and tools for:

- Components
- Templates
- Routing and navigation
- Forms and validation
- Dependency injection
- Services
- Testing and build tooling

Angular does not remove the need to understand web development. It gives the team a shared structure so that developers do not have to invent the entire application architecture from scratch.

### A useful analogy

A small roadside stall can operate with a few informal practices. A restaurant with multiple branches benefits from repeatable procedures, clear responsibilities, and shared standards.

Angular is not the restaurant. It is the set of tools and conventions that helps a larger team operate consistently.

### Example connection

In a clinic application:

- An appointment list could be a reusable Angular component.
- A doctor page could combine several components.
- Routing could display the correct screen for each URL.
- A service could hold reusable application logic.

These features belong to later lessons. Day 1 focuses on the basic application structure and setup.

### Minimal mental model

```text
User opens the site
        ↓
Browser receives application files
        ↓
Angular starts the application
        ↓
Angular creates the root component
        ↓
The component template and styles appear on screen
```

A **component** is a part of the user interface with associated logic, an HTML template, and optionally CSS styles.

---

### 2. What does Angular provide?

Angular gives a team a clear way to organize a large, interactive website.

| Need | Angular feature | Simple meaning |
|---|---|---|
| Break a screen into manageable pieces | Components | Reusable sections of the user interface |
| Connect data to HTML | Templates and data binding | Display and update values on the page |
| Respond to user actions | Event handling | React to clicks, typing, and other events |
| Move between screens | Routing | Show different views for different URLs |
| Reuse logic | Services | Keep shared logic in one place |
| Create and run projects | Angular CLI | Automate setup, development, and builds |

For a small static page, Angular may be more than you need. For a growing, interactive application, its structure can make the code easier to understand and maintain.

---

### 3. Angular compared with basic web technologies

| Technology | Main responsibility |
|---|---|
| HTML | Defines the page structure |
| CSS | Controls appearance and layout |
| JavaScript | Adds behavior and interaction |
| Angular | Organizes HTML, styling, logic, navigation, forms, and reusable features into an application structure |

Angular still uses HTML, CSS, and JavaScript concepts. It gives them a framework, conventions, and tools for building a complete application.

## Part 2 — Prepare the Windows machine

### 4. Install Node.js and npm

#### Why do we need Node.js if Angular runs in a browser?

Angular's development tools run on your computer. Node.js executes those tools, and npm downloads the packages they need.

This does **not** mean that the Angular user interface is a Node.js server application. Node.js is being used here for development tooling.

#### Installation steps

1. Open [nodejs.org](https://nodejs.org/).
2. Download a supported LTS release.
3. Run the Windows installer using the normal defaults, including adding Node.js to PATH.
4. Close and reopen your terminal or VS Code.
5. Verify the installation:

```powershell
node --version
npm --version
```

You should see version numbers rather than a command-not-found error.

Angular and Node.js compatibility changes over time. Always check the [official Angular compatibility table](https://angular.dev/reference/versions) before installing or upgrading. Do not assume that every Node.js version works with every Angular version.

#### Explain it back

```text
Node.js → runs development tools
npm     → installs and manages packages
```

They are related, but they solve different problems.

---

### 5. Install Visual Studio Code

1. Visit [code.visualstudio.com](https://code.visualstudio.com/) and install VS Code.
2. Open VS Code.
3. Open **Terminal → New Terminal**.
4. Optionally install the official **Angular Language Service** extension.
5. Verify the tools again in the integrated terminal:

```powershell
node --version
npm --version
```

Remember:

- VS Code is the editor.
- The terminal runs commands.
- Angular CLI creates and manages Angular projects.

---

### 6. Install the Angular CLI

The Angular CLI automates repeatable tasks such as creating project folders, generating configuration files, serving the application, and building it.

Install it globally:

```powershell
npm install -g @angular/cli
ng version
```

What these commands mean:

- `npm install` installs a package.
- `-g` makes the CLI available from different project folders.
- `ng version` displays Angular tooling and project version information.

#### Windows PowerShell note

If PowerShell blocks `ng.ps1` or `npm.ps1`, use Command Prompt or call `ng.cmd` / `npm.cmd` instead. If your machine policy permits it, the Angular documentation also describes:

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

This changes script execution policy for the current user. Follow company IT policy and do not use administrator-wide or unrestricted policies blindly.

### Checkpoint A

The following commands should all return valid version information:

```powershell
node --version
npm --version
ng version
```

## Part 3 — Create and run your first Angular application

We will create a small onboarding welcome screen and use it to explore Angular's project structure.

### 7. Create a workspace and application

In the VS Code terminal or Command Prompt:

```powershell
mkdir angular-learning
cd angular-learning
ng new intern-welcome
```

During project creation, Angular may ask configuration questions. For this beginner exercise, choose:

- **CSS** for styling.
- The default **standalone** application structure.
- **No** for server-side rendering (SSR), unless your course specifically requires it.

The exact prompts can change between Angular CLI versions. The default choices are generally suitable for a first project.

### What is a workspace?

A workspace is the directory that stores the Angular application's source code and configuration files. The command creates the project structure and normally installs the required npm dependencies.

### 8. Open the project in VS Code

```powershell
cd intern-welcome
code .
```

If `code .` is not recognized, open the folder manually through **VS Code → File → Open Folder** and select `angular-learning/intern-welcome`.

### 9. Start the application

```powershell
ng serve --open
```

This starts the development server and usually opens:

```text
http://localhost:4200/
```

- `localhost` means this computer.
- `4200` is the usual Angular development port.
- `ng serve` watches the project for changes and rebuilds it.

Stop the server with **Ctrl+C** in the terminal.

### Checkpoint B

The generated Angular page appears in the browser, and the terminal does not show build errors.

## Part 4 — Understand the project structure

Think of the project as an office:

- The workspace root contains office-wide policies and supplies.
- `src/` contains the application source code.
- `src/app/` contains the root screen and application logic.
- `public/` contains static files served directly by the development server.

### 10. Typical project structure

Exact files vary depending on Angular version, routing, tests, and the options selected during project creation.

```text
intern-welcome/
├── .editorconfig
├── .gitignore
├── angular.json
├── package.json
├── package-lock.json
├── node_modules/
├── public/
├── tsconfig.json
├── tsconfig.app.json
├── tsconfig.spec.json       (if tests are configured)
└── src/
    ├── index.html
    ├── main.ts
    ├── styles.css
    └── app/
        ├── app.ts
        ├── app.html
        ├── app.css
        ├── app.config.ts    (in standalone projects)
        ├── app.routes.ts    (if routing is configured)
        └── app.spec.ts      (if tests are configured)
```

### 11. Important files and folders

| File or folder | Purpose | Beginner use |
|---|---|---|
| `package.json` | Records packages and project scripts | Install dependencies or run scripts |
| `package-lock.json` | Records resolved dependency versions | Normally maintained by npm and committed with the project |
| `node_modules/` | Contains installed packages | Do not edit manually or commit normally |
| `angular.json` | Configures Angular build, serve, and test tooling | Change assets or build configuration under guidance |
| `tsconfig.json` | Shared TypeScript configuration | Rarely changed in beginner exercises |
| `tsconfig.app.json` | TypeScript settings for application compilation | Usually left unchanged initially |
| `tsconfig.spec.json` | TypeScript settings for tests | Used when configuring tests |
| `.gitignore` | Lists files Git should ignore | Check that local/generated files are excluded |
| `.editorconfig` | Helps keep formatting consistent | Supports team-wide editor rules |
| `public/` | Static images and other public files | Add images or other static assets |
| `src/index.html` | HTML document shell that hosts the Angular app | Rarely edited; useful for title and metadata |
| `src/main.ts` | Starts or bootstraps the Angular application | Occasionally changed for startup configuration |
| `src/styles.css` | Global styles | Set site-wide typography or background styles |
| `src/app/app.ts` | Root component logic and metadata | Add data, behavior, and component settings |
| `src/app/app.html` | Root component template | Edit the visible screen structure and text |
| `src/app/app.css` | Root component styles | Style the root component |
| `src/app/app.config.ts` | Application-wide provider configuration | Used later for framework features and services |
| `src/app/app.routes.ts` | Maps URL paths to views/components | Used later when adding pages |
| `src/app/app.spec.ts` | Automated tests for the root component | Used later when writing tests |

### Version note

Older Angular tutorials may use names such as `app.component.ts`, `app.component.html`, `app.component.css`, or `app.module.ts`. Those files belong to a different project-generation style. Always follow the files actually created by your project.

### 12. Trace the startup path

Read these files in order:

1. **`src/index.html`** — find the root element, commonly `<app-root></app-root>`.
2. **`src/main.ts`** — see where Angular starts the application.
3. **`src/app/app.ts`** — identify `@Component`, `selector`, `templateUrl`, and `styleUrl` or `styleUrls`.
4. **`src/app/app.html`** — find the content visible in the browser.
5. **`src/app/app.css`** — find styles specific to the root component.

The mental model is:

```text
main.ts starts Angular
        ↓
Angular creates the root component
        ↓
The root selector is placed in index.html
        ↓
The component template renders inside it
        ↓
The component and global styles are applied
```

### Important distinction

- `index.html` is the document shell.
- `app.html` is the root Angular component's template.

Do not confuse the two files.

## Part 5 — Hands-on lab: make your first changes

Use the `intern-welcome` application you just created.

### Task 1: Change the template

Open `src/app/app.html` and replace the starter markup with:

```html
<main class="welcome-page">
  <h1>Welcome to Angular Training</h1>
  <p>Day 1: My first Angular application</p>
  <button type="button">Start Learning</button>
</main>
```

Save the file and observe the browser. Since `ng serve` watches for changes, the page should update without restarting the server.

The button does not do anything yet. Adding behavior belongs to a later lesson.

**Think:** Why did editing `app.html` change the page without editing `index.html`?

### Task 2: Style the page

Open `src/app/app.css` and add:

```css
.welcome-page {
  max-width: 650px;
  margin: 80px auto;
  padding: 32px;
  text-align: center;
  border: 1px solid #dddddd;
  border-radius: 12px;
}

h1 {
  color: #263b7a;
}

button {
  padding: 12px 20px;
  cursor: pointer;
}
```

Change one property at a time. Before saving, predict what `padding`, `color`, `max-width`, or `border-radius` will change.

### Task 3: Inspect the TypeScript connection

Open `src/app/app.ts` and identify:

- The component class name.
- The value that connects the component to `app.html`.
- The value that connects the component to `app.css`.
- The selector that corresponds to the root element in `index.html`.

Do not rewrite the whole file. The goal is to understand the connections.

### Task 4: Change global styles

Open `src/styles.css` and add:

```css
body {
  margin: 0;
  font-family: Arial, sans-serif;
  background-color: #f5f7fb;
}
```

Compare the effect:

- `styles.css` contains global site-wide styles.
- `app.css` contains styles for the root component.

### Task 5: Explore the project safely

- Locate Angular package versions in `package.json`.
- Check whether `.gitignore` excludes `node_modules`.
- Find the `serve` and `build` configuration in `angular.json` without changing it.
- Find `main.ts` and explain its startup responsibility.
- Add a small image to `public/` and display it using `/filename.ext` as the source.

## Part 7 — Common problems and debugging

| Symptom | Likely cause | First action |
|---|---|---|
| `'node' is not recognized` | Node.js is missing or PATH has not refreshed | Install a supported Node.js version, reopen the terminal, and retry |
| `'npm' is not recognized` | Node.js/npm is missing from PATH | Recheck the installation and PATH |
| `'ng' is not recognized` | Angular CLI is not installed or its executable is not on PATH | Reinstall the CLI, reopen the terminal, and retry |
| PowerShell refuses to run `.ps1` files | Script execution policy | Use Command Prompt or follow an organization-approved policy |
| Port 4200 is already in use | Another process is serving on that port | Stop the previous server or use `ng serve --port 4201` |
| Template edits do not appear | Wrong file/folder, stopped server, or build failure | Check the terminal folder, browser URL, and build output |
| Errors after editing `app.ts` | TypeScript or component metadata syntax error | Undo the last change and fix one issue at a time |

### Debugging rule

Read the first useful error message before reinstalling tools or deleting folders. Change one variable at a time.
