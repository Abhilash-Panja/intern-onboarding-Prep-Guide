# Angular Child-to-Parent Communication

Child-to-parent communication means sending data or events from a child component to its parent component.

```text
Child → Parent
```

Angular supports three common approaches:

1. Template reference variable
2. `@ViewChild`
3. `@Output()` with `EventEmitter`

A useful way to remember them is:

```text
#child       → parent template accesses the child
@ViewChild   → parent TypeScript accesses the child
@Output()    → child sends an event to the parent
```

---

# Example Scenario

We have:

```text
StudentDashboard  ← Parent
StudentCard       ← Child
```

The child contains student information, and the parent wants to receive it.

---

# 1. Using a Template Reference Variable

## What is it?

A template reference variable gives the parent template a reference to the child component.

It is created using `#`.

```html
<app-student-card #studentCard></app-student-card>
```

Here, `studentCard` refers to the child component instance.

## Child component

```typescript
export class StudentCard {
  studentName = 'Abhi';
}
```

## Parent template

```html
<app-student-card #studentCard></app-student-card>

<p>Student Name: {{ studentCard.studentName }}</p>
```

The parent reads the child’s `studentName` property directly.

The flow is:

```text
Child studentName
        ↓
#studentCard reference
        ↓
Parent template
```

The parent can also pass the value to a parent method:

```html
<app-student-card #studentCard></app-student-card>

<button
  (click)="receiveStudentName(studentCard.studentName)">
  Read Student Name
</button>
```

```typescript
export class StudentDashboard {
  receiveStudentName(name: string) {
    console.log(name);
  }
}
```

## Important point

A template reference variable is available only inside the template.

It cannot be directly used inside the parent’s TypeScript class.

---

# 2. Using the `@ViewChild` Decorator

## What is it?

`@ViewChild` allows the parent component’s TypeScript class to access a child component.

```typescript
@ViewChild(StudentCard)
studentCard!: StudentCard;
```

Now the parent can read the child’s properties or call its methods.

## Child component

```typescript
import { Component } from '@angular/core';

@Component({
  selector: 'app-student-card',
  template: `
    <p>Student Name: {{ studentName }}</p>
  `
})
export class StudentCard {
  studentName = 'Abhi';

  getStudentName() {
    return this.studentName;
  }
}
```

## Parent component

```typescript
import {
  AfterViewInit,
  Component,
  ViewChild
} from '@angular/core';

import { StudentCard } from './student-card';

@Component({
  selector: 'app-student-dashboard',
  imports: [StudentCard],
  templateUrl: './student-dashboard.html'
})
export class StudentDashboard implements AfterViewInit {
  @ViewChild(StudentCard)
  studentCard!: StudentCard;

  receivedName = '';

  ngAfterViewInit() {
    console.log(this.studentCard.studentName);
  }

  readStudentName() {
    this.receivedName = this.studentCard.getStudentName();
  }
}
```

## Parent template

```html
<app-student-card></app-student-card>

<button (click)="readStudentName()">
  Read Student Name
</button>

<p>Received Name: {{ receivedName }}</p>
```

When the button is clicked:

```text
Parent calls child method
        ↓
Child returns student name
        ↓
Parent stores the returned value
```

## Important lifecycle rule

The child is available only after Angular creates the view.

Therefore, use `@ViewChild` inside:

```typescript
ngAfterViewInit()
```

Do not expect the child to be available inside the constructor or usually inside `ngOnInit()`.

# 3. Using `@Output()` and `EventEmitter`

## What is it?

`@Output()` allows the child to actively notify the parent.

This is the most common and recommended approach when the child needs to send data because of an event.

```text
Child emits data → Parent listens and receives data
```

## Child component

```typescript
import {
  Component,
  EventEmitter,
  Output
} from '@angular/core';

@Component({
  selector: 'app-student-card',
  template: `
    <p>Student Name: {{ studentName }}</p>

    <button (click)="sendStudentName()">
      Send Name to Parent
    </button>
  `
})
export class StudentCard {
  studentName = 'Abhi';

  @Output()
  studentNameSent = new EventEmitter<string>();

  sendStudentName() {
    this.studentNameSent.emit(this.studentName);
  }
}
```

The important line is:

```typescript
this.studentNameSent.emit(this.studentName);
```

This sends the child’s student name to the parent.

## Parent component

```typescript
export class StudentDashboard {
  receivedName = '';

  receiveStudentName(name: string) {
    this.receivedName = name;
  }
}
```

## Parent template

```html
<app-student-card
  (studentNameSent)="receiveStudentName($event)">
</app-student-card>

<p>Received Name: {{ receivedName }}</p>
```

## Understanding `$event`

```html
(studentNameSent)="receiveStudentName($event)"
```

`$event` contains the data emitted by the child.

The flow is:

```text
Child button clicked
        ↓
sendStudentName()
        ↓
studentNameSent.emit('Abhi')
        ↓
Parent receives $event
        ↓
receiveStudentName('Abhi')
```

---

# Comparing the Three Approaches

| Approach | Where it is used | Direction |
|---|---|---|
| Template reference variable | Parent template | Parent reads child |
| `@ViewChild` | Parent TypeScript class | Parent accesses child |
| `@Output()` | Child event communication | Child notifies parent |

## Simple decision rule

Use a template reference variable when:

```text
The parent template only needs to read or call something on the child.
```

Use `@ViewChild` when:

```text
The parent TypeScript class needs to access the child.
```

Use `@Output()` when:

```text
The child needs to notify the parent about an event or send data.
```

---

# Important Difference

Template reference variables and `@ViewChild` allow the parent to access the child.

This is called a parent-driven approach:

```text
Parent pulls data from Child
```

`@Output()` allows the child to notify the parent.

This is a child-driven approach:

```text
Child pushes data to Parent
```

For normal application communication, `@Output()` is usually preferred because it keeps the child and parent more loosely connected.
