# Angular Component Communication

## 1. What is a component?

A component is an independent part of an Angular application that contains:

- A TypeScript class
- An HTML template
- Optional CSS styles
- Its own logic and data

For example, a student-management application may contain:

```text
StudentDashboard
StudentCard
StudentList
StudentForm
Header
Sidebar
```

Each component has its own responsibility.

For example:

- `StudentDashboard` manages the dashboard.
- `StudentCard` displays one student.
- `StudentForm` collects student information.

Because each component has its own data and logic, components need a way to communicate with one another.

---

# 2. What is component communication?

Component communication is the process of passing data, sending events, or sharing information between Angular components.

Imagine components as employees in a company:

- One employee owns some information.
- Another employee needs that information.
- They need a proper communication method to exchange it.

Similarly, Angular components communicate through specific patterns.

Without component communication:

- Components would become isolated.
- Data would be duplicated.
- Reusable components would be difficult to create.
- The application would become harder to maintain.

---

# 3. How are components related?

Angular components usually form a tree structure.

```text
AppComponent
│
└── StudentDashboard        ← Parent
    │
    └── StudentCard         ← Child
```

The relationship between components determines how they should communicate.

The two most important communication directions are:

```text
Parent → Child
Child → Parent
```

---

# 4. Common types of component communication

## 4.1 Parent-to-child communication

The parent sends data to the child.

```text
Parent
  │
  │ data
  ▼
Child
```

Angular uses:

```typescript
@Input()
```

Example:

- The parent owns the student name.
- The child displays the student name.

```typescript
// Parent
name = 'Abhi';
```

```html
<!-- Parent template -->
<app-student-card [studentName]="name"></app-student-card>
```

```typescript
// Child
@Input() studentName = '';
```

---

## 4.2 Child-to-parent communication

The child sends an event or information to the parent.

```text
Parent
  ▲
  │ event
  │
Child
```

Angular commonly uses:

```typescript
@Output()
EventEmitter
```

Example:

- The child contains a Delete button.
- The child tells the parent that the button was clicked.
- The parent performs the delete operation.

```typescript
// Child
@Output() deleteStudent = new EventEmitter<number>();
```

```html
<!-- Parent template -->
<app-student-card
  (deleteStudent)="removeStudent($event)">
</app-student-card>
```

This is the reverse direction of `@Input()`.

---

## 4.3 Communication between unrelated components

Sometimes two components do not have a direct parent-child relationship.

```text
AppComponent
├── Header
└── StudentDashboard
```

For this situation, Angular commonly uses a shared service.

```text
Component A
     │
     ▼
Shared Service
     │
     ▼
Component B
```

For larger applications, developers may also use state-management solutions.

---

# 5. The most important mental model

Remember this:

```text
@Input()  = information enters the child
@Output() = information exits the child
```

Or:

```text
Parent → Child = @Input()
Child → Parent = @Output()
```

Since we are currently learning parent-to-child communication, we will focus on `@Input()`.

---

# Parent-to-Child Communication Using `@Input()`

## 6. The problem we want to solve

Suppose we have two components:

```text
StudentDashboard       ← Parent
StudentCard            ← Child
```

The parent contains this data:

```typescript
name = 'Abhi';
```

The child should display:

```text
Student Name: Abhi
```

But the child has its own TypeScript class and template.

So how can the child receive the parent’s value?

The answer is:

```typescript
@Input()
```

---

# 7. What exactly does `@Input()` do?

`@Input()` creates a communication channel from the parent to the child.

The parent owns the data:

```typescript
name = 'Abhi';
```

The child declares that it can receive data:

```typescript
@Input() studentName = '';
```

The parent connects its property to the child’s input:

```html
<app-student-card [studentName]="name"></app-student-card>
```

The complete flow is:

```text
Parent property
      ↓
Property binding
      ↓
Child @Input() property
      ↓
Child template
```

---

# 8. Building the example step by step

## Step 1: Create the child component

### `student-card.ts`

```typescript
import { Component, Input } from '@angular/core';

@Component({
  selector: 'app-student-card',
  templateUrl: './student-card.html'
})
export class StudentCard {
  @Input() studentName = '';
}
```

The important line is:

```typescript
@Input() studentName = '';
```

This means:

> Angular, allow the parent component to provide a value for `studentName`.

The empty string is the initial value.

---

## Step 2: Display the value in the child

### `student-card.html`

```html
<h2>Student Name: {{ studentName }}</h2>
```

The child displays whatever value Angular assigns to `studentName`.

At this point, the child is ready to receive data, but the parent has not passed anything yet.

---

## Step 3: Create the parent data

### `student-dashboard.ts`

```typescript
import { Component } from '@angular/core';

@Component({
  selector: 'app-student-dashboard',
  templateUrl: './student-dashboard.html'
})
export class StudentDashboard {
  name = 'Abhi';
}
```

The parent owns the actual data:

```typescript
name = 'Abhi';
```

The child does not need to know where this value came from.

---

## Step 4: Pass the data to the child

### `student-dashboard.html`

```html
<app-student-card [studentName]="name"></app-student-card>
```

This is property binding.

The binding can be understood like this:

```html
[childInput]="parentProperty"
```

In this example:

```html
[studentName]="name"
```

- `studentName` is the child’s `@Input()` property.
- `name` is the parent’s property.

Read the complete line as:

> Take the `name` value from the parent and assign it to the child’s `studentName` property.

---

# 9. What happens when Angular runs the application?

Angular performs the following steps:

### 1. The parent stores the data

```typescript
name = 'Abhi';
```

### 2. Angular evaluates the binding

```html
[studentName]="name"
```

### 3. Angular sends the value to the child

```typescript
studentName = 'Abhi';
```

### 4. The child displays the value

```text
Student Name: Abhi
```

The complete flow is:

```text
name = 'Abhi'
      ↓
[studentName]="name"
      ↓
@Input() studentName
      ↓
{{ studentName }}
      ↓
Student Name: Abhi
```

---

# 10. Why are square brackets important?

This syntax:

```html
[studentName]="name"
```

means:

> Evaluate `name` as a property or expression.

Without square brackets:

```html
<app-student-card studentName="name"></app-student-card>
```

Angular treats `"name"` as a normal text value.

The child would receive:

```text
name
```

not:

```text
Abhi
```

Therefore:

```html
[studentName]="name"
```

passes the value of the parent property.

---

# 11. The left side and right side rule

This is one of the most important rules to remember:

```html
[childProperty]="parentProperty"
```

Example:

```html
[studentName]="name"
```

| Side | Meaning |
|---|---|
| Left side: `studentName` | Child’s `@Input()` property |
| Right side: `name` | Parent’s property |

The names do not need to be identical.

For example:

### Parent

```typescript
courseName = 'Angular Basics';
```

### Child

```typescript
@Input() course = '';
```

### Parent template

```html
<app-child [course]="courseName"></app-child>
```

The value flows like this:

```text
courseName = 'Angular Basics'
              ↓
       [course]="courseName"
              ↓
course = 'Angular Basics'
```

---

# 12. What if the parent value changes?

Suppose the parent initially has:

```typescript
name = 'Abhi';
```

The child displays:

```text
Student Name: Abhi
```

Later, the parent changes the value:

```typescript
name = 'Rahul';
```

Angular automatically updates the child:

```text
Student Name: Rahul
```

This is because the child’s input is connected to the parent’s property.

The direction remains:

```text
Parent → Child
```

This is called one-way data flow.

---

# 13. Complete example

## Child component

### `student-card.ts`

```typescript
import { Component, Input } from '@angular/core';

@Component({
  selector: 'app-student-card',
  template: `
    <h2>Student Name: {{ studentName }}</h2>
  `
})
export class StudentCard {
  @Input() studentName = '';
}
```

## Parent component

### `student-dashboard.ts`

```typescript
import { Component } from '@angular/core';
import { StudentCard } from './student-card';

@Component({
  selector: 'app-student-dashboard',
  imports: [StudentCard],
  template: `
    <app-student-card
      [studentName]="name">
    </app-student-card>
  `
})
export class StudentDashboard {
  name = 'Abhi';
}
```

## Result

```text
Student Name: Abhi
```

# 14. Passing different types of data

`@Input()` can receive different types of values.

## String

```typescript
title = 'Student Details';
```

```html
<app-card [title]="title"></app-card>
```

## Number

```typescript
age = 22;
```

```html
<app-student [age]="age"></app-student>
```

## Boolean

```typescript
isActive = true;
```

```html
<app-student [isActive]="isActive"></app-student>
```

## Object

```typescript
student = {
  name: 'Abhi',
  course: 'Angular'
};
```

```html
<app-student-card [student]="student"></app-student-card>
```

## Array

```typescript
students = ['Abhi', 'Rahul', 'Priya'];
```

```html
<app-student-list [students]="students"></app-student-list>
```

The child input type should match the data being passed.

---

# 15. Why is `@Input()` useful?

`@Input()` makes components reusable.

Without `@Input()`, a `StudentCard` might contain a fixed name:

```typescript
studentName = 'Abhi';
```

That component would work only for Abhi.

With `@Input()`:

```typescript
@Input() studentName = '';
```

The same component can display many students:

```html
<app-student-card [studentName]="'Abhi'"></app-student-card>

<app-student-card [studentName]="'Rahul'"></app-student-card>

<app-student-card [studentName]="'Priya'"></app-student-card>
```

The child becomes reusable because it does not own the actual student data. It only receives and displays it.

---

# 16. Responsibilities of the parent and child

## Parent responsibility

The parent should:

- Own the data
- Prepare the data
- Pass the data to the child
- Decide when the data changes

## Child responsibility

The child should:

- Declare the required input
- Receive the data
- Display or use the data
- Avoid directly changing the parent’s data

This separation keeps the application organized.

---

# 17. Common mistakes

## Mistake 1: Forgetting `@Input()`

Incorrect:

```typescript
studentName = '';
```

Correct:

```typescript
@Input() studentName = '';
```

---

## Mistake 2: Using the wrong input name

Child:

```typescript
@Input() course = '';
```

Correct parent binding:

```html
<app-child [course]="courseName"></app-child>
```

Incorrect:

```html
<app-child [courseName]="course"></app-child>
```

The name on the left must match the child’s input property.

---

## Mistake 3: Forgetting the import

```typescript
import { Component, Input } from '@angular/core';
```

---

## Mistake 4: Confusing property binding with event binding

Parent-to-child data transfer:

```html
[studentName]="name"
```

Child-to-parent event transfer:

```html
(studentDeleted)="handleDelete($event)"
```

Remember:

```text
[] = send data into the child
() = listen for an event from the child
```

---

## Mistake 5: Passing a property that does not exist

If the parent has:

```typescript
studentName = 'Abhi';
```

This is correct:

```html
<app-student-card [studentName]="studentName"></app-student-card>
```

But this is incorrect if `name` does not exist in the parent:

```html
<app-student-card [studentName]="name"></app-student-card>
```

Angular can only bind to properties that actually exist in the parent component.

---

# 18. A simple real-world analogy

Think of a restaurant:

- The parent component is the kitchen.
- The child component is the waiter.
- The kitchen prepares the food.
- The waiter receives the food and presents it to the customer.

The waiter does not prepare the food. The waiter receives what the kitchen provides.

Similarly:

```text
Parent prepares data
        ↓
Child receives data
        ↓
Child displays data
```

That is exactly how `@Input()` works.

---

# 19. Quick comparison with Spring Boot

This is only a conceptual comparison:

| Angular concept | Similar idea |
|---|---|
| Parent component | Owns or prepares data |
| Child component | Consumes the data |
| `@Input()` | Defines what data the child accepts |
| Property binding | Supplies the value |
| Child template | Uses the received value |

However, Angular’s `@Input()` is not an HTTP request and is not the same as a Java method parameter. It is Angular’s built-in mechanism for component communication.

# 20. Final mental picture

Whenever you see this:

```typescript
@Input() studentName = '';
```

Think:

> This child is ready to receive `studentName` from its parent.

Whenever you see this:

```html
<app-student-card [studentName]="name"></app-student-card>
```

Think:

> The parent is sending its `name` value into the child’s `studentName` input.

The entire concept can be remembered as:

```text
Parent owns the data
        ↓
Parent passes the data using property binding
        ↓
Child receives it through @Input()
        ↓
Child displays or uses it
```
