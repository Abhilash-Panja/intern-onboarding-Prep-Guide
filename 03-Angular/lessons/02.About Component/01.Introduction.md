# Angular Components

## 1. What is a component?

A component is a reusable part of an Angular application's user interface.

For example, a task-tracking page can be divided into smaller components:

```text
Task Tracker Page
│
├── Header Component
├── Task Form Component
└── Task List Component
```

Each component manages one specific part of the screen.

This makes the application:

- Easier to understand
- Easier to reuse
- Easier to test
- Easier to maintain

---

## 2. What does a component contain?

A component usually contains three important parts:

| Part | Responsibility |
|---|---|
| TypeScript class | Stores data and contains behavior |
| HTML template | Defines what appears on the screen |
| CSS styles | Defines how the component looks |

The relationship is:

```text
TypeScript class
       ↓
Provides data and behavior
       ↓
HTML template
       ↓
Displays the data
       ↓
CSS styles
       ↓
Controls the appearance
```

# 3. Create a component

Run this command inside your Angular project:

```powershell
ng generate component components/task-list
```

You can also use the shorter version:

```powershell
ng g c components/task-list
```

Angular creates a folder similar to this:

```text
src/app/components/task-list/
│
├── task-list.ts
├── task-list.html
├── task-list.css
└── task-list.spec.ts
```

The test file may be generated depending on your project configuration.

---

# 4. Define the task data

The component uses a `ProjectTask` type to describe a task.

For example:

### `task.model.ts`

```typescript
export interface ProjectTask {
  id: number;
  title: string;
  completed: boolean;
  priority: 'low' | 'medium' | 'high';
  status: 'todo' | 'in-progress' | 'done';
}
```

This tells TypeScript what information every task should contain.

A task must have:

```text
id
title
completed
priority
status
```

# 5. Create the component class

Open `task-list.ts`:

```typescript
import { Component } from '@angular/core';
import { ProjectTask } from '../../models/task.model';

@Component({
  selector: 'app-task-list',
  templateUrl: './task-list.html',
  styleUrl: './task-list.css'
})
export class TaskList {
  tasks: ProjectTask[] = [
    {
      id: 1,
      title: 'Learn Angular components',
      completed: false,
      priority: 'high',
      status: 'todo'
    },
    {
      id: 2,
      title: 'Build a task page',
      completed: true,
      priority: 'medium',
      status: 'done'
    }
  ];
}
```

## Understanding the code

### The import statements

```typescript
import { Component } from '@angular/core';
import { ProjectTask } from '../../models/task.model';
```

- `Component` allows us to create an Angular component.
- `ProjectTask` describes the structure of a task.

### The `@Component` decorator

```typescript
@Component({
  selector: 'app-task-list',
  templateUrl: './task-list.html',
  styleUrl: './task-list.css'
})
```

The decorator gives Angular information about the component:

| Property | Meaning |
|---|---|
| `selector` | The HTML name used to display the component |
| `templateUrl` | The HTML file used by the component |
| `styleUrl` | The CSS file used by the component |

### The component class

```typescript
export class TaskList {
}
```

This class contains the component's data and behavior.

### The `tasks` property

```typescript
tasks: ProjectTask[] = [
  // task objects
];
```

This means:

- `tasks` is the property name.
- `ProjectTask[]` means it is an array of `ProjectTask` objects.
- The array contains the tasks displayed by the template.

# 6. Create the component template

Open `task-list.html`:

```html
<h2>My Tasks</h2>

@if (tasks.length === 0) {
  <p>No tasks available.</p>
}

@for (task of tasks; track task.id) {
  <article>
    <h3>{{ task.title }}</h3>

    <p>Priority: {{ task.priority }}</p>
    <p>Status: {{ task.status }}</p>

    @if (task.completed) {
      <span>Completed</span>
    } @else {
      <span>Open</span>
    }
  </article>
}
```

---

## 7. Understand the template syntax

### Displaying a property

```html
<h3>{{ task.title }}</h3>
```

This is called interpolation.

Angular reads the value of `task.title` from the component class and displays it in the HTML.

```text
task.title → HTML
```

### Checking whether the list is empty

```html
@if (tasks.length === 0) {
  <p>No tasks available.</p>
}
```

This means:

> If the tasks array contains zero items, display “No tasks available.”

### Looping through tasks

```html
@for (task of tasks; track task.id) {
}
```

This means:

> For every task in the `tasks` array, repeat this block of HTML.

For the example data, Angular creates two `<article>` elements.

### Why use `track task.id`?

```html
@for (task of tasks; track task.id)
```

`track task.id` gives Angular a unique identifier for each task. This helps Angular update the correct item efficiently when the list changes.

### Checking the task status

```html
@if (task.completed) {
  <span>Completed</span>
} @else {
  <span>Open</span>
}
```

This means:

- If `completed` is `true`, display `Completed`.
- Otherwise, display `Open`.

# 8. Use the component

A component is not displayed automatically just because it was created.

We must use its selector inside another component.

Open the root component, usually:

```text
app.ts
```

or, in older projects:

```text
app.component.ts
```

Example:

```typescript
import { Component } from '@angular/core';
import { TaskList } from './components/task-list/task-list';

@Component({
  selector: 'app-root',
  imports: [TaskList],
  template: `
    <h1>Task Tracker</h1>

    <app-task-list></app-task-list>
  `
})
export class App {}
```

## Two important things happen here

### 1. Import the component

```typescript
import { TaskList } from './components/task-list/task-list';
```

This tells the root component where the `TaskList` component is located.

### 2. Add the component to `imports`

```typescript
imports: [TaskList]
```

This makes `TaskList` available inside the root component's template.

### 3. Use the selector

```html
<app-task-list></app-task-list>
```

This displays the `TaskList` component.

The selector was defined here:

```typescript
selector: 'app-task-list'
```

Angular uses that selector as a custom HTML element:

```html
<app-task-list></app-task-list>
```

The complete connection is:

```text
selector: 'app-task-list'
              ↓
<app-task-list></app-task-list>
              ↓
TaskList component appears on the page
```

```text

```

# 10. Complete component flow

```text
TaskList class
      │
      │ provides the tasks array
      ▼
TaskList template
      │
      │ displays each task
      ▼
Angular renders HTML
      │
      │ applies component styles
      ▼
User sees the task list in the browser
```

A component works as one connected unit:

```text
TypeScript class + HTML template + CSS styles
```

# 11. Common beginner mistakes

## Mistake 1: Using the wrong selector

If the component has:

```typescript
selector: 'app-task-list'
```

Use:

```html
<app-task-list></app-task-list>
```

Do not use:

```html
<task-list></task-list>
```

---

## Mistake 2: Forgetting the component import

The parent must import the component:

```typescript
import { TaskList } from './components/task-list/task-list';
```

For standalone components, it must also be added to:

```typescript
imports: [TaskList]
```

---

## Mistake 3: Using the wrong property name

The component class has:

```typescript
tasks
```

Therefore, the template must use:

```html
tasks
```

Not:

```html
taskList
```

---

## Mistake 4: Forgetting `track` in `@for`

Use:

```html
@for (task of tasks; track task.id) {
}
```

The `id` should be unique for every task.

---

## Mistake 5: Confusing global and component styles

```text
src/styles.css              → global application styles
task-list.css               → styles for TaskList
```

Use `task-list.css` for styles that belong only to the task-list component.
