# Angular Component Lifecycle Hooks

## 1. What is a component lifecycle?

A component goes through different stages during its lifetime:

```text
Component is created
        ↓
Angular provides input data
        ↓
Component is initialized
        ↓
Component may receive updated data
        ↓
Component is removed
```

Angular provides lifecycle hooks so we can run code at specific stages.

The three important hooks are:

```text
ngOnChanges  → input data changes
ngOnInit     → component initialization
ngOnDestroy  → component removal
```

---

# 2. Lifecycle order

For a component that receives data from a parent, the simplified order is:

```text
constructor()
      ↓
ngOnChanges()
      ↓
ngOnInit()
      ↓
Component runs and updates
      ↓
ngOnChanges() whenever an input changes
      ↓
ngOnDestroy() before removal
```

Important:

- `constructor()` is not a lifecycle hook.
- `ngOnChanges()` runs when an `@Input()` value changes.
- `ngOnInit()` runs once after the component receives its initial input values.
- `ngOnDestroy()` runs before Angular removes the component.

---

# 3. Constructor vs `ngOnInit`

This is a common beginner confusion.

## Constructor

The constructor runs first, when Angular creates the component class.

Use the constructor mainly for:

- Dependency injection
- Very basic property initialization

Example:

```typescript
constructor(private taskApi: TaskApiService) {
}
```

The constructor should not usually contain complex component initialization logic.

## `ngOnInit`

`ngOnInit()` runs after Angular has created the component and initialized its input values.

Use it for:

- Initial API calls
- Loading configuration
- Initial calculations
- Preparing component data
- Initialization that depends on `@Input()` values

Example:

```typescript
import {
  Component,
  OnInit
} from '@angular/core';

@Component({
  selector: 'app-task-list',
  templateUrl: './task-list.html'
})
export class TaskList implements OnInit {
  tasks: string[] = [];

  ngOnInit(): void {
    console.log('TaskList component initialized');

    this.tasks = [
      'Learn Angular',
      'Build a task page'
    ];
  }
}
```

`ngOnInit()` runs only once for that component instance.

---

## Modern dependency injection with `inject()`

Modern Angular also allows dependency injection using `inject()`:

```typescript
import { Component, inject } from '@angular/core';

@Component({
  selector: 'app-task-list',
  templateUrl: './task-list.html'
})
export class TaskList {
  private taskApi = inject(TaskApiService);
}
```

This is still dependency injection. It is simply an alternative to constructor injection.

```text
Constructor injection:
constructor(private taskApi: TaskApiService) {}

Modern inject function:
private taskApi = inject(TaskApiService);
```

# 4. `ngOnChanges`

## What is `ngOnChanges`?

`ngOnChanges()` runs when a value received through `@Input()` changes.

The data flow is:

```text
Parent component
        ↓
@Input() property in child
        ↓
ngOnChanges()
```

Use it when the child needs to perform some work whenever the parent sends new input data.

---

## Example

### Child component

```typescript
import {
  Component,
  Input,
  OnChanges,
  SimpleChanges
} from '@angular/core';

@Component({
  selector: 'app-task-item',
  templateUrl: './task-item.html'
})
export class TaskItem implements OnChanges {
  @Input() taskName = '';

  ngOnChanges(changes: SimpleChanges): void {
    console.log('Task input changed:', changes);
  }
}
```

### Parent template

```html
<app-task-item [taskName]="selectedTask"></app-task-item>
```

### Parent component

```typescript
export class TaskDashboard {
  selectedTask = 'Learn Angular';
}
```

When the parent changes:

```typescript
selectedTask = 'Build a task page';
```

Angular updates the child’s `taskName` input and runs:

```typescript
ngOnChanges()
```

---

# 5. Understanding `SimpleChanges`

`SimpleChanges` contains information about the input that changed.

```typescript
ngOnChanges(changes: SimpleChanges): void {
  const taskChange = changes['taskName'];

  if (taskChange) {
    console.log('Previous value:', taskChange.previousValue);
    console.log('Current value:', taskChange.currentValue);
    console.log('First change:', taskChange.firstChange);
  }
}
```

It provides:

- `previousValue` — the old input value
- `currentValue` — the new input value
- `firstChange` — whether this is the first input update

---

# 6. Important facts about `ngOnChanges`

`ngOnChanges()`:

- Runs for values received through `@Input()`.
- Runs once initially when the input is first supplied.
- Runs again when the input value changes.
- Runs before `ngOnInit()` during the initial setup.
- Does not run just because any normal child property changes.

For object or array inputs, Angular usually detects a change when the object or array reference changes.

Example:

```typescript
this.task = {
  id: 1,
  title: 'Updated task'
};
```

This creates a new object reference, so Angular can detect the input change.

# 7. `ngOnDestroy`

## What is `ngOnDestroy`?

`ngOnDestroy()` runs immediately before Angular removes a component from the page.

This can happen when:

- A condition removes the component.
- The user navigates to another route.
- A dynamic component is removed.
- The parent no longer displays the child.

Example:

```typescript
import {
  Component,
  OnDestroy
} from '@angular/core';

@Component({
  selector: 'app-task-list',
  templateUrl: './task-list.html'
})
export class TaskList implements OnDestroy {
  ngOnDestroy(): void {
    console.log('TaskList component destroyed');
  }
}
```

---

# 8. What should be cleaned up in `ngOnDestroy`?

Use `ngOnDestroy()` for cleanup work such as:

- Clearing timers
- Removing event listeners
- Closing connections
- Stopping long-running subscriptions
- Releasing resources created by the component

Example:

```typescript
export class TaskList implements OnDestroy {
  private timerId = setInterval(() => {
    console.log('Checking tasks...');
  }, 5000);

  ngOnDestroy(): void {
    clearInterval(this.timerId);
    console.log('Timer cleared');
  }
}
```

Regular HTTP requests usually complete automatically. Long-running streams, timers, and manual subscriptions may require cleanup.

---

# 9. Complete lifecycle summary

| Stage | Hook | When it runs | Common use |
|---|---|---|---|
| Creation | `constructor()` | When the class is created | Dependency injection |
| Input update | `ngOnChanges()` | When an `@Input()` value changes | React to parent data |
| Initialization | `ngOnInit()` | Once after initial inputs are ready | Initial setup and API calls |
| Removal | `ngOnDestroy()` | Before Angular removes the component | Cleanup |

---

# 10. Constructor vs `ngOnInit` vs `ngOnChanges`

## Use the constructor when:

```text
You need dependency injection.
```

```typescript
constructor(private taskApi: TaskApiService) {
}
```

## Use `ngOnChanges` when:

```text
You need to react to changed @Input() data.
```

```typescript
ngOnChanges(changes: SimpleChanges): void {
}
```

## Use `ngOnInit` when:

```text
You need to initialize the component after its inputs are ready.
```

```typescript
ngOnInit(): void {
}
```

## Use `ngOnDestroy` when:

```text
You need to clean up before the component disappears.
```

```typescript
ngOnDestroy(): void {
}
```

# Quick revision

```text
constructor() → dependency injection
ngOnChanges() → @Input() data changes
ngOnInit()     → one-time initialization
ngOnDestroy()  → cleanup before removal
```

The most important lifecycle flow is:

```text
constructor()
      ↓
ngOnChanges()
      ↓
ngOnInit()
      ↓
Component runs
      ↓
ngOnChanges() when @Input() changes
      ↓
ngOnDestroy()
```

## One-line takeaway

> Angular lifecycle hooks allow you to run code when a component is created, when its input data changes, and just before it is removed.
