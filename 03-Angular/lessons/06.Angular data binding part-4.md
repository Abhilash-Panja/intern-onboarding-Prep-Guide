# Angular Two-Way Binding for Beginners

*Part 4 of my Angular data binding series (the last one!)*

So far in this series I have learned three types of data binding: **interpolation**, **property binding**, and **event binding**. Each one moves data in a single direction. Now it's time for the final type, **two-way binding**, which moves data in *both* directions at the same time.

## 1. A Quick Recap

- **Interpolation (`{{ }}`):** Component to page, shows text.
- **Property binding (`[ ]`):** Component to element, sets properties.
- **Event binding (`( )`):** Page to component, reacts to user actions.
- **Two-way binding (`[( )]`):** Both ways, today's topic.

## 2. What Is Two-Way Binding?

In two-way binding, data flows in both directions:

1. **From the component (`.ts`) to the view template (HTML):** The input box shows the value stored in the component.
2. **From the view template back to the component:** When the user types something new, the component's value is updated immediately.

So the component and the page are always in sync. If either one changes, the other changes too.

Two-way binding is mostly used with **form elements** such as input boxes, dropdowns, and checkboxes, where the user can change the value.

## 3. The `ngModel` Directive

To enable two-way binding, Angular gives us a directive called **`ngModel`**. We write it with a special syntax:

```html
<input [(ngModel)]="username" />
```

The syntax `[( )]` is often called **"banana in a box"**, because the round brackets look like a banana inside the square brackets of a box.

The reason it looks like that is simple. Two-way binding is a combination of the two bindings we already know:

- **`[ ]` Property binding:** Sends data to the element.
- **`( )` Event binding:** Brings data back from the element.

Put together, `[( )]` does both jobs in one.

## 4. How to Use Two-Way Binding: Step by Step

### Step 1: Import `FormsModule`

The `ngModel` directive does not work by default. It belongs to Angular's `FormsModule`, so you must import it in your component.

Open `data-binding.ts`:

```typescript
import { Component } from '@angular/core';
import { FormsModule } from '@angular/forms';

@Component({
  imports: [FormsModule],
  selector: 'app-data-binding',
  styleUrl: './data-binding.css',
  templateUrl: './data-binding.html',
})
export class DataBinding {
  username = 'Abhi';
}
```

There are two things to notice:

- `FormsModule` is imported at the top.
- It is also added to the component's `imports` array.

Both are needed when using this standalone component setup.

### Step 2: Use `ngModel` in the HTML File

Open `data-binding.html`:

```html
<input [(ngModel)]="username" placeholder="Enter your name" />

<p>Hello, {{ username }}!</p>
```

### Step 3: Test It in the Browser

When the page loads, the input box already shows "Abhi", which is the data flowing from the component to the view.

Now start typing in the box. The line below it changes with every keystroke, which is the data flowing from the view back to the component.

We did not write a single method to handle the typing. `ngModel` took care of everything.

## 5. Comparing with Event Binding

In the event binding post, we built the same thing manually:

```html
<input (input)="onTyping($event)" />

<p>You typed: {{ message }}</p>
```

That needed a method in the `.ts` file to read the input and update the variable.

With two-way binding, the same result takes just one line:

```html
<input [(ngModel)]="message" />

<p>You typed: {{ message }}</p>
```

That is why two-way binding is so popular for forms.

## 6. Two-Way Binding with Other Form Elements

### 6.1 Dropdown

```html
<select [(ngModel)]="course">
  <option value="Angular">Angular</option>
  <option value="React">React</option>
  <option value="Vue">Vue</option>
</select>

<p>Selected: {{ course }}</p>
```

### 6.2 Checkbox

```html
<input type="checkbox" [(ngModel)]="isSubscribed" />

<p>Subscribed: {{ isSubscribed }}</p>
```

For these examples, add the following properties to your `.ts` file:

```typescript
course = 'Angular';
isSubscribed = false;
```

## 7. Common Mistakes to Avoid

### Mistake 1: Forgetting to Import `FormsModule`

If you skip it, you will see an error like:

```text
Can't bind to 'ngModel' since it isn't a known property of 'input'.
```

**The fix:** Import `FormsModule` from `@angular/forms` and add it to the component's `imports` array.

### Mistake 2: Writing the Brackets in the Wrong Order

```html
<!-- Wrong -->
<input ([ngModel])="username" />

<!-- Correct -->
<input [(ngModel)]="username" />
```

Remember the banana is inside the box: the round brackets go **inside** the square brackets.

### Mistake 3: Binding to Something That Does Not Exist

The name in the quotes must be a real property in your `.ts` file.

For example:

```html
<input [(ngModel)]="username" />
```

Your component must declare the corresponding property:

```typescript
username = '';
```

If `username` is not declared in the class, you will get a template error.

## 8. Rules to Remember

- Two-way binding uses `[(ngModel)]`, the "banana in a box".
- Data flows **both ways**: component to view and view to component.
- You must import **`FormsModule`** to use `ngModel`.
- It is used mainly with form elements like inputs, dropdowns, and checkboxes.
- It is a shortcut for property binding plus event binding.

## 9. All Four Bindings Together

| Binding | Syntax | Direction | Used for |
|---|---|---|---|
| Interpolation | `{{ }}` | Component to page | Showing text |
| Property binding | `[ ]` | Component to element | Setting element properties |
| Event binding | `( )` | Template to component | Reacting to user actions |
| Two-way binding | `[( )]` | Both ways | Keeping inputs and data in sync |

## 11. Series Summary

- **Data binding** connects the data in your `.ts` file with the view in your `.html` file.
- **Interpolation (`{{ }}`)** shows values as text.
- **Property binding (`[ ]`)** sets element properties from data.
- **Event binding (`( )`)** handles user actions and can lead to saving data through a backend API.
- **Two-way binding (`[(ngModel)]`)** keeps the component and the view in sync in both directions.
