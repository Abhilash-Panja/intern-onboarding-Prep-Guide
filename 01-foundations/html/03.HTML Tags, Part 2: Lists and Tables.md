# Day 3 — HTML Tags, Part 2: Lists and Tables

**Goal:** Organize information using the correct list or table.  
**Time:** About 60–90 minutes, including practice.

## 1. Why do we need lists and tables?

Imagine a shopping app:

- **Shopping categories** are a list: they don't need rows and columns.
- **Checkout steps** are an ordered list: sequence matters.
- **Product prices** are a table: each price belongs to a specific product.

**Rule:** Choose HTML based on the *relationship between the information*, not its appearance.

## 2. Lists: three types

| Type | Use when | Main tags |
| --- | --- | --- |
| Unordered list | Order doesn't matter | `<ul>`, `<li>` |
| Ordered list | Sequence or ranking matters | `<ol>`, `<li>` |
| Description list | Terms have descriptions or values | `<dl>`, `<dt>`, `<dd>` |

### Unordered list — `<ul>`

```html
<h2>Available Services</h2>
<ul>
  <li>General consultation</li>
  <li>Vaccination</li>
  <li>Health checkup</li>
</ul>
```

The browser usually displays bullet points. `<li>` represents each item.

### Ordered list — `<ol>`

```html
<h2>Book an Appointment</h2>
<ol>
  <li>Choose a doctor</li>
  <li>Select a time slot</li>
  <li>Confirm your appointment</li>
</ol>
```

The browser usually displays numbers. Changing the order changes the instructions.

### Description list — `<dl>`

```html
<h2>Appointment Details</h2>
<dl>
  <dt>Doctor</dt>
  <dd>Dr. Meera</dd>
  <dt>Time</dt>
  <dd>10:30 AM</dd>
</dl>
```

- `<dt>` names the term or property.
- `<dd>` gives its description or value.
- `<dl>` groups those term-description pairs.

**Remember:** A description list is not restricted to dictionary definitions; it also works for related names and values.

## 3. Tables: data in rows and columns

Use a table when readers need to compare values under common headings, such as appointments, marks, or invoices.

| Tag / attribute | Purpose |
| --- | --- |
| `<table>` | Entire data table |
| `<caption>` | Short title describing the table |
| `<tr>` | One row |
| `<th>` | Header cell |
| `<td>` | Data cell |
| `<thead>` / `<tbody>` / `<tfoot>` | Optional header, main, and summary groups |
| `scope="col"` / `scope="row"` | Identifies which cells a header describes |
| `colspan="2"` | Makes one cell span two columns |

### Example — appointment report

```html
<table>
  <caption>Today's Appointments</caption>
  <thead>
    <tr>
      <th scope="col">Patient</th>
      <th scope="col">Time</th>
      <th scope="col">Status</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Ravi</td>
      <td>10:00 AM</td>
      <td>Completed</td>
    </tr>
    <tr>
      <td>Anita</td>
      <td>10:30 AM</td>
      <td>Scheduled</td>
    </tr>
  </tbody>
  <tfoot>
    <tr>
      <th scope="row" colspan="2">Total Appointments</th>
      <td>2</td>
    </tr>
  </tfoot>
</table>
```

**How to read the code:** `<thead>` holds the column names, `<tbody>` the appointment rows, and `<tfoot>` the total. `colspan="2"` combines the first two columns in the last row. `scope` makes header relationships clearer for assistive technology.

**Note:** HTML gives the table its meaning. Borders, spacing, and mobile layout are CSS topics. Avoid the outdated `border="1"` HTML attribute in new code.

## 4. Common mistakes

- Using `<ol>` for items whose order doesn't matter, or `<ul>` for a numbered process.
- Putting `<li>` directly inside a `<div>` instead of a list container.
- Using a table to position page sections instead of displaying data.
- Using `<td>` for column headings rather than `<th>`.
- Thinking `<thead>`, `<tbody>`, and `<tfoot>` are mandatory for every simple table; use them when they clarify the structure.

## 5. Hands-on task — Student Course Dashboard

Create one **`index.html`** page with HTML only. Do not copy the examples word for word.

**Requirements:**

1. Add an unordered list with at least three subjects.
2. Add an ordered list with at least three steps for enrolling in a course.
3. Add a description list with at least two course details (for example, duration and instructor).
4. Add a table showing at least three students with **Name**, **Course**, and **Progress** columns.
5. Give the table a `<caption>`, use `<th scope="col">` for its column headings, and organize rows using `<thead>` and `<tbody>`.

**Expected result:** One readable HTML page containing three distinct list types and a student progress table.

**Self-check:**

- [ ] I chose each list type for the correct reason.
- [ ] My table headings match the data below them.
- [ ] All list items and table cells are nested correctly.
- [ ] I can explain the difference between `<th>` and `<td>`.
- [ ] The page works without CSS or JavaScript.

**Optional challenge:** Add a `<tfoot>` row with the total number of students. Use `colspan` correctly.

2. A product has a name, size, and material. When could `<dl>` be useful?
3. Why is `<th>` better than `<td>` for a column heading?
4. What does `colspan="2"` change?
