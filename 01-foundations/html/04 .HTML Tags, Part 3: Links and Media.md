# Day 4 — HTML Tags, Part 3: Links and Media

**Goal:** Link pages and display images, audio, video, and embedded content correctly.    
**Time:** About 60–90 minutes, including practice.

## 1. Why do we need links and media?

A clinic website needs a link to its booking page, a photo of the entrance, and perhaps a short introduction video. **HTML links connect destinations; media elements present content.**

| Element | What it does | Typical use |
| --- | --- | --- |
| `<a>` | Creates a hyperlink | Open another page or jump to a section |
| `<img>` | Displays an image | Product photo, illustration, logo |
| `<video>` | Plays a video | Product demo, tutorial |
| `<audio>` | Plays sound | Podcast, voice instructions |
| `<iframe>` | Embeds another HTML document | Map, supported video embed |

## 2. Links — `<a>`

```html
<a href="https://developer.mozilla.org/">Read MDN documentation</a>
<a href="#contact">Jump to contact details</a>

<h2 id="contact">Contact</h2>
<p>Email the clinic to ask a question.</p>
```

- `href` tells the browser **where to go**. A URL can be external, a local page path, or `#contact` for a section with `id="contact"`.
- The text between `<a>` and `</a>` should describe the destination; avoid vague labels such as “Click here.”
- `target="_blank"` usually opens a new tab or window. Modern browsers implicitly protect such links with `noopener`; specifying `rel="noopener"` makes the intention clear:

```html
<a href="https://developer.mozilla.org/" target="_blank" rel="noopener">
  Open MDN in a new tab
</a>
```

**Remember:** A link's `title` attribute is optional extra information, not a replacement for meaningful visible link text.

## 3. Images — `<img>`

```html
<img
  src="images/clinic-entrance.jpg"
  alt="Entrance of the demo clinic"
  width="480"
  height="320"
>
```

- `src` points to the image file. **Create the `images` folder and add that file** for this example to display.
- `alt` describes useful information conveyed by the image to someone who cannot see it. Use `alt=""` for a purely decorative image.
- `width` and `height` are pixel dimensions that help the browser reserve space before the image loads; use the image's actual aspect ratio.

**Common use:** An online store uses meaningful `alt` text for product images. Avoid writing just “image” or stuffing keywords into it.

## 4. Video and audio — `<video>`, `<audio>`

```html
<video controls width="480">
  <source src="media/clinic-tour.mp4" type="video/mp4">
  Your browser does not support HTML video.
</video>

<audio controls>
  <source src="media/welcome.mp3" type="audio/mpeg">
  Your browser does not support HTML audio.
</audio>
```

**For this example to play**, create a `media` folder and add your own files with those names.

- `controls` shows browser playback controls: play, pause, seeking, and volume where supported.
- `<source>` provides a file and its media type. Multiple sources can offer different formats.
- `loop` repeats media. `autoplay` **does not guarantee playback**: browsers commonly block autoplay with sound. Let the visitor choose to play.
- For spoken videos, supply accurate captions (commonly via `<track>` with a `.vtt` file). Provide a transcript where appropriate; audio-only content also benefits from one.

## 5. Embedded pages — `<iframe>`

An iframe puts another HTML document *inside* your page. This small example works without any external website:

```html
<iframe
  title="Demo clinic opening hours"
  srcdoc="<p>Mon–Fri: 9 AM–5 PM</p>"
  width="320"
  height="100"
></iframe>
```

- `title` tells assistive technology **what is inside the frame**.
- `src` normally points to a page or an official embeddable URL; `srcdoc` supplies a small inline HTML document.
- Some websites **block embedding**, so a normal website URL is not guaranteed to work in an iframe. Use the provider's approved embed link for maps or hosted videos.
- `frameborder` is obsolete. Use CSS for borders and responsive sizing when you learn styling.

## 6. Common mistakes

- Writing `href="<https://example.com>"` instead of `href="https://example.com"`.
- Forgetting meaningful `alt` text, or giving a decorative image an unnecessary description.
- Using a file path that does not exist (`images/photo.jpg` without the image file).
- Assuming `autoplay` always works or adding media without playback controls.
- Embedding arbitrary external pages and expecting every iframe to display.
- Using `width="100%"` for media element dimensions. Use numeric HTML dimensions; responsive sizing belongs in CSS.

## 7. Hands-on task — Course Information Page

Build one **`index.html`** page using HTML only. Create your own content instead of copying the code above.

**Requirements:**

1. Add an `<h1>` and an introduction paragraph.
2. Add two links: one to a useful external learning website, and one that jumps to a section on the same page.
3. Add one meaningful image with `src`, `alt`, `width`, and `height` (provide the real image file).
4. Add one video and one audio player with `controls` (provide files you own or are allowed to use).
5. Add an `<iframe>` with a descriptive `title`. You may use `srcdoc`, as demonstrated above.

**Expected result:** Users can follow both links, see the image, play both media files, and identify the embedded document.

**Self-check:**

- [ ] My external link opens its intended destination and my internal link jumps correctly.
- [ ] My image loads and its `alt` text conveys the image's purpose.
- [ ] My video and audio files play with visible controls.
- [ ] My iframe has a useful `title` and displays its content.
- [ ] I can explain the difference between a link (`<a>`) and an embed (`<iframe>`).

**Optional challenge:** Add a video caption track using `<track>` and a valid `.vtt` file.
